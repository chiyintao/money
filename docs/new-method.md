# 新方法：选币 / 训练 / 决策 的完整循环

> **先给结论。** 我把当前数据和三种候选方案都实测了一遍，结果是负面的：
> 在现有特征和数据上，**任何视野、任何门槛都得不到统计上站得住的净收益**。
>
> 所以「没有开仓」在很大程度上是**闸门做对了事**，不是坏的。
> 真正要改的不是门槛，是**先建立一条能证明 edge 存在的研究流水线**，
> 并接受「证明不出来就不交易」是一个合法状态。

---

## 一、先说清楚：为什么现在必然不开仓

### 1.1 成本决定了最低命中率

```
盈利条件： 命中率 × 平均盈利 > (1−命中率) × 平均亏损 + 成本
近似为：   所需命中率 = 50% + 成本 / (2 × 平均绝对波动)
```

本机 12 个主流币、367 天、5m 数据实测（126 万根）：

| 持有期 | 平均\|波动\| | 所需命中率 | 模型实测 | 结论 |
|---|---|---|---|---|
| 5m | 18.9 bp | **81.8%** | ~50% | 不可能 |
| 15m | 34.1 bp | 67.6% | ~50% | 不可能 |
| 1h | 72.4 bp | 58.3% | ~50% | 不可能 |
| 4h | 151.8 bp | 54.0% | ~50% | 不可能 |
| 24h | 418.7 bp | 51.4% | ~50% | 勉强，但样本太少 |

**关键不是「4h 需要 54% 所以改 4h 就行」，而是模型在哪个视野上都没有 54%。**

### 1.2 实测：换视野救不了（我改正过一次错误结论）

我最初用「全样本分十档」做检验，得出 4h 有 +8.79bp 的结论 —— **那是错的**，
因为跨全样本排序用到了未来信息。改成**每个时间戳内横截面排序**（可真实交易的口径）后：

```
特征        视野    组差bp   净bp     调整后t
f_ema20     1h       1.39   -10.61     1.36
f_ema20     2h       2.05    -9.95     1.04
f_ema20     4h       1.72   -10.28     0.46
f_ema20     8h      -0.70   -12.70    -0.10
f_mom12     4h       0.96   -11.04     0.26
f_ret10     4h       0.80   -11.20     0.21
```

**没有一档为正。** 组差本身就只有 1–2bp，而成本是 12bp。

### 1.3 实测：模型也没有 edge

用现有 10 特征、88 万行训练、37.7 万行测试（含 1 小时禁运期），
按 `|预测|` 分档看真实净收益：

```
|预测|档      样本      占比     命中率    净均值bp      t值
0-2       224099   59.36%    49.7%    -11.91   -115.81
2-5        87362   23.14%    48.8%    -13.07    -61.71
10-12       6153    1.63%    51.0%    -12.13    -10.79
20-30       4794    1.27%    50.2%    -11.48     -6.77
>50         3204    0.85%    51.2%     +0.77      0.27   ← 唯一的正值，但是噪声
```

**命中率在所有档位都是 49–51%，即模型没有方向识别能力。**
最高置信档的 +0.77bp，t 值 0.27，统计上与 0 无法区分。

### 1.4 实测：换成高波动小币也不显著

把品种按日波动率分成两组，各训一个模型：

```
组别              视野   门槛   净bp    t原    t非重叠   命中率
低波动(主流币)      1h     10   -14.81  -10.45   -3.72    47.9%
低波动(主流币)      4h     10   -16.50  -13.84   -1.58    48.0%
高波动(小币)        1h     50   +15.98   +2.04   +0.22    52.0%
高波动(小币)        4h     50   +26.81   +3.20   +1.44    50.7%
```

小币看起来是正的，但**重叠样本把 t 值抬高了**：按非重叠抽样重算，
t 只有 0.22 和 1.44，**达不到 2，不能认为是真 edge**。
主流币则明确为负。

### 1.5 那到底缺什么

```
不是缺配置，不是缺门槛调参，是：
  · 特征只有 10 个（v3），全部是价格/成交量衍生 → 信息量已被榨干
  · 30 个特征（v4）里的 OI / flow / liquidation 族，本机覆盖率仅 0.68%
  · 资金费率历史只有 59,604 行，且 mark 曲线有断点（DOTUSDT 落后 511 分钟）
  · 品种池只有 12 个主流币，波动太小；小币有波动但数据不足
```

## 二、新方法的三个决定

### 决定 1：把「证明有 edge」变成流水线的第一等公民

现在的流程是 `下载 → 建数据集 → 训练 → 晋升`，**没有「拒绝」这一环**。
一个没有 edge 的模型会一路走到线上，然后被闸门拦住 —— 系统看起来「不工作」，
实际是闸门在替研究流程背锅。

新流程**每一步都可能失败，且失败是正常输出**：

```
数据 → 特征 → 标签 → 训练 → ┌─ 验收门禁 ─┐ → 通过 → 上线
                              │ 不过 → 丢弃，记录原因
                              └────────────┘
```

### 决定 2：成本是一等约束，不是事后扣减

```
现在：训练时按 12bp 扣，实盘也按 12bp → 两面都卡死
新方法：把成本降到 4–6bp（挂单），并让标签在【生成时】就带成本
```

| 往返成本 | 5m 所需命中率 | 1h 所需 | 4h 所需 |
|---|---|---|---|
| 12 bp（现在，市价） | 81.8% | 58.3% | 54.0% |
| 6 bp（单边挂单） | 65.9% | 54.1% | 52.0% |
| **4 bp（双边挂单）** | **60.6%** | **52.8%** | **51.3%** |

4bp 时 4h 只需 51.3% —— 这是模型**可能**达到的水平。所以降成本不是优化，是前提。

### 决定 3：视野由成本算出来，不由手感定

```
选择规则：所需命中率 ≤ 54%（现代梯度提升在加密上的现实上限）
  → 4h 以上
  → 取 horizon = 48 根（4h），并让退出策略、元标签全部对齐到同一个数
```

## 三、① 选币：稳定候选池 + 信号驱动持仓

### 3.1 核心改变：池子稳定，持仓动态

```
旧：每 2–3 分钟按涨幅榜换币 → 模型来不及积累任何证据（已修复，但设计仍是错的）
新：候选池【每天刷新一次】，持仓【由信号驱动】

    候选池（每天 00:00 重算）        持仓（随时）
    流动性 + 波动 + 训练域    →    只有出信号才建仓
    15–20 个，稳定                  0–5 个，动态
```

### 3.2 三层筛选（全部可用现有数据算）

```
第 1 层 可交易性
  · 日成交额 ≥ 500 万 USDT
  · 上市 ≥ 90 天（≥ 26,000 根 5m）
  · 单根跳空 < 20%（剔除坏数据）

第 2 层 成本可覆盖性   ← 这一层决定策略能否成立
  · 4h 平均绝对波动 ≥ 4 × 往返成本（12bp 成本下即 ≥ 48bp）
  · 近 30 天 / 近 90 天波动比 ∈ [0.5, 2.0]（排除波动衰减）

第 3 层 训练域一致
  · 必须在训练集品种池内（否则 OOD 正确拦截）
```

### 3.3 本机实测候选池

```
54 个有 5m 数据的品种
  日成交额 ≥ 500万U  → 约 20 个
  4h 波动 ≥ 48bp     → 约 15 个
  最终候选池         → 10–15 个
```

**关键**：候选池必须与训练品种池**完全一致**。
这是本次排查中最贵的一课 —— 训练域与交易域不相交，OOD 会拦掉 100%。

## 四、② 训练：一条会「拒绝」的流水线

### 4.1 数据要求

| 项目 | 现在 | 目标 |
|---|---|---|
| 品种池 | 12 个主流币 | 15–20 个（含高波动） |
| 特征 | 10 个（v3） | 30 个（v4），且覆盖率 ≥ 80% |
| 历史 | 367 天 | ≥ 365 天，每品种 ≥ 10 万根 |
| 标签视野 | 12 根（1h） | 48 根（4h） |
| 标签障碍 | 对称 1:1 | 与实盘 `exit_policy` **同一个函数** |
| 成本 | 事后扣 12bp | 生成时就按 4–6bp 写进标签 |

`build_dataset(..., exit_policy=load_exit_policy("swing"))` —— 代码已支持，只是没启用。
训练用什么障碍，实盘就必须用什么障碍，否则学的是另一个策略。

### 4.2 验收门禁（不达标就丢弃，这是新流程的核心）

| 指标 | 门槛 | 为什么 |
|---|---|---|
| 测试集方向准确率 | ≥ 54% | 低于此无法覆盖 4h 成本 |
| 活跃样本净 edge | > 0 bp | 已扣成本 |
| **非重叠样本 t 值** | **≥ 2** | 重叠样本会把 t 抬高 3–7 倍（本次实测） |
| Deflated Sharpe Ratio | ≥ 1.0 | 惩罚多重检验 |
| PBO | ≤ 0.5 | 过拟合概率 |
| 活跃样本占比 | ≥ 1% | 0.14% 意味着一周可能一笔都没有 |

**非重叠 t 值是新增的，也是最容易被忽略的。** 4h 视野下每根 bar 的标签重叠 48 次，
直接算 t 会虚高约 7 倍。必须按 `step = horizon` 抽样重算。

### 4.3 走查验证

```
walk-forward：按季度滚动，每折只用过去数据训练
每折都必须独立通过 4.2 的门禁
任何一折不通过 → 模型不晋升
```

## 五、③ 决策：门槛顺序与「正确地不交易」

### 5.1 闸门顺序（信息量从高到低）

```
1. 数据完整？（feature_degraded）        ← 数据问题，最高优先级
2. 品种在训练域内？（symbol_not_in_training）
3. 特征在分布内？（out_of_distribution）
4. 模型有方向？（no_directional_edge）
5. 成员一致？（agreement_below_floor）
6. 净 edge 够？（edge_below_floor）
7. 该品种历史够？（symbol_edge）        ← 元标签，最后
```

每一层都要**记录原因码**，且**全部评估、不做 if/elif 短路** —— 否则第一个触发的闸门
会掩盖下面所有闸门，运维看不到真实分布（这一点代码已经改对了）。

### 5.2 元标签（symbol_edge）必须与模型同视野

```
旧：SYMBOL_EDGE_HORIZON_BARS=3，模型 12 根 → 测的不是同一个东西
新：= 48，与模型一致
保留：proposed_side（记录模型提出的方向，而非过闸后的 side）
      market.bar_time（记录决策锚定的 bar）
```

这两项是本轮修复的核心。没有它们，`seed_from_history()` 只能从「已被压成 FLAT」的
审计行重建证据，导致闸门对自己拦住的品种永远学不到东西。

### 5.3 「不交易」是合法状态，但要可观测

```
当所有品种都被拦住时，系统应该：
  · 继续记录每条决策的原因码（已做）
  · 在 /health 里给出「今日拦截原因分布」
  · 当拦截率 = 100% 持续超过 N 小时 → 告警，因为这说明模型或数据退化
```

## 六、④ 执行：把成本从 12bp 降到 4bp

这是**投入产出比最高的一项**。成本减半，所需命中率下降 5–20 个百分点。

```
现在：市价进 + 市价出 = 2 × (5bp 手续费 + 1bp 滑点) = 12bp
新方法：
  · 入场：限价挂单（maker），手续费 5bp → 2bp，滑点 → 0
  · 出场：优先限价；仅止损用市价
  · 4h 持有期意味着大部分仓位能等到挂单成交
  → 平均 4–6bp
实现：限价单路径 + 超时转市价（FILL_TIMEOUT），即路线图 P3 #21
```

## 七、⑤⑥ 循环：让它自己转，且能收敛

### 7.1 时间表

```
每天 00:00   重算候选池（流动性 + 波动 + 训练域）
每周一 00:00 下载上周数据（全部候选池品种）
每周一 01:00 数据质量检查（覆盖率、断点、异常值）
每周一 02:00 重建数据集（4h 视野 + exit_policy 一致 + 30 特征）
每周一 04:00 训练 + 走查验证 + 门禁判定
每周一 06:00 通过则晋升，否则保留旧模型并告警
实时         决策循环（不改）
每月         复核候选池与成本假设
```

### 7.2 每次循环的产出（必须落盘）

```
每次训练必须保存：
  · 门禁各指标的实测值（不是「通过/失败」）
  · 被拒绝的原因
  · 非重叠 t 值（新增）
  · 数据覆盖率快照
这样 3 个月后才能回答「为什么这个模型被拒了」。
```

### 7.3 每笔交易必须可归因

```
现在：94 笔历史交易 reason_detail 全空 → 退出策略无法评估
新：{exit_reason, bars_held, mae, mfe, slippage_bps, entry_order_type,
     model_edge_bps, symbol, session_id}
```

## 八、落地顺序

| 步 | 动作 | 依赖 | 验收 |
|---|---|---|---|
| **0** | 把「非重叠 t」加入训练评估 | 无 | 能算出该指标 |
| **1** | 回补 15–20 品种 1 年数据 + v4 特征覆盖率 ≥ 80% | 无 | 覆盖率报告 |
| **2** | 启用 `exit_policy` 一致的标签 + horizon=48 | 1 | 标签分布合理 |
| **3** | 重训并跑门禁 | 1,2 | **能否通过 §4.2** |
| **4** | 限价单执行路径（12bp → 4bp） | 无 | 实测成本 ≤ 6bp |
| **5** | 候选池模块 + 每日刷新 | 1 | 池子稳定，不再换币 |
| **6** | 交易归因字段 + 每周脚本 | 3,5 | 每笔有 reason_detail |

**第 3 步是生死判定。** 如果补完数据、换完视野后门禁仍不通过，
说明这组特征里没有 4h 尺度的预测信息，需要换信息源（资金费率历史、
持仓量变化、跨市场价差、链上数据），而不是继续调模型。

## 九、新旧对照

| 维度 | 旧 | 新 | 理由 |
|---|---|---|---|
| 流程终点 | 训练完就上线 | 先过门禁，可拒绝 | 没 edge 的模型不该上线 |
| 选币 | 24h 涨幅榜 | 流动性 + 波动 + 训练域 | 涨幅与盈利无关 |
| 候选池 | 每 2–3 分钟换 | 每天刷新 | 换币使模型无法积累证据 |
| 品种池 | 12 主流币 | 15–20（含高波动） | 主流币波动不足成本 |
| 视野 | 12 根 | 48 根 | 按成本算出 |
| 标签 | 对称障碍 | 与实盘 exit_policy 一致 | 训练与实盘必须同源 |
| 特征 | 10 个 | 30 个 | v4 含 OI/flow/liquidation |
| 成本 | 12bp 市价 | 4–6bp 挂单 | 所需命中率降 5–20 点 |
| 显著性 | 重叠 t | **非重叠 t ≥ 2** | 重叠使 t 虚高约 7 倍 |
| 元标签视野 | 3 根 | 48 根 | 与模型同视野 |
| 不交易 | 视为故障 | 视为合法状态 | 闸门在正确工作 |

## 十、一句话总结

> **当前系统没有可交易的 edge，这是实测结论，不是配置问题。**
>
> 5m 交易需要 81.8% 命中率，模型只有 50%；换到 4h 只需 54%，但模型在 4h 上仍然只有 50%。
> 高波动小币看起来有 +27bp，非重叠 t 却只有 1.44，站不住。
>
> 所以要做的三件事，按顺序：
> **① 补数据**（v4 特征覆盖率、更多高波动品种、完整资金费率历史）
> **② 降成本**（市价 12bp → 挂单 4bp）
> **③ 建门禁**（非重叠 t ≥ 2、DSR ≥ 1、PBO ≤ 0.5，不达标就拒绝上线）
>
> 在这三件事完成之前，**系统不开仓是正确的**。
