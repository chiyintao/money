# 预测模型诊断与重构方案

> 结论先行：**当前模型不是"调参不够好"，而是它被要求回答一个数学上无法支付成本的问题。**
> 用 30 个技术指标预测 5 分钟 K 线的 1 小时方向，在扣掉 12bp 成本后，
> 期望边际必然是负的。证据不是我的意见，是你自己 manifest 里的数字。

## 一、实测证据（来自你自己的产物，非推测）

扫描 `data/research_v3/candidates*/*/manifest.json`，16 个候选模型**没有一个**通过：

| 指标 | 实测值 | 需要达到 | 结论 |
|---|---|---|---|
| 方向准确率 | 49.2% ~ 51.7% | > 52%（扣费后） | 等同抛硬币 |
| 扣费后净边际 | **−7.6 ~ −18.6 bp** | > +12 bp | 稳定为负 |
| bootstrap P(edge>0) | 0.08 ~ 0.27 | ≥ 0.95 | 远不显著 |
| 组合样本外收益 | **−17% ~ −27%** | > 0 | 亏损 |
| 组合样本外 Sharpe | −3.0 ~ −3.4 | > 0 | 稳定亏损 |
| 胜率 | ~35% | > 50% | — |
| active_share（敢于交易的占比） | 0.02% ~ 0.35% | 有意义的样本量 | 几乎没有信号 |

模型自己的 verdict 字段原文写着：

> `"no edge established"`
> `"out-of-sample edge is negative (-10.28 bp): this would lose money"`
> `"confidence interval straddles zero"`

**校准还把结果变差了**：ECE 从 0.0071 变成 0.1006，Brier 从 0.2499 变成 0.2636，
`improved: false`。这说明模型输出的概率本身也不含信息——不是"阈值没调好"，
而是排序能力本身不存在，isotonic 只是在拟合噪声。

## 二、根因诊断（三个层次，按严重程度排序）

### 根因 1：标签的噪声尺度和成本尺度不匹配 —— 这是数学问题，不是工程问题

从 40 万行样本实测：

```
三重障碍标签的收益分布 sd  = 70.0 bps
运行时假设的往返成本      = 12 bps
=> 成本 = 0.17 个标准差
```

同时障碍命中率本身就是负偏的：

```
upper（止盈）37.48%   lower（止损）39.14%   vertical（时间）23.38%
```

**止损先被打到的概率高于止盈**，所以这个策略在扣费前胜率就低于 50%。
再叠加 12bp 往返成本，等于每笔交易一开始就欠市场 12bp。

要做到扣费后为正，你需要把**每笔的期望收益挪动超过 12bp = 0.17σ**。
在 1 小时尺度上，靠 EMA/RSI/ATR 这类特征产生 0.17σ 的方向偏移，
意味着预测 R² 需要达到约 3% 以上。而加密货币 5 分钟到 1 小时尺度上的
公开研究一致表明：**方向预测的可解释 R² 通常在 0.1% 以下**，比需要的低一个数量级。

> 这就是为什么反复训练、换模型、加特征都没用——你在要求 GBDT 从噪声里
> 提取一个比成本小一个数量级的信号，然后把成本压上去。**信息论上不成立。**

### 根因 2：30 个特征里有 7 个是死的，真正的信息面比想象的窄得多

从 `training_dataset_mainstream.jsonl.profile.json` 的 bounds 实测：

| 特征 | 在 99.8% 分位范围内的值 |
|---|---|
| `flow_delta_ratio` | 恒为 0.0 |
| `flow_delta_z` | 恒为 0.0 |
| `flow_trade_intensity_z` | 恒为 0.0 |
| `flow_largest_trade_z` | 恒为 0.0 |
| `liquidation_pressure` | 恒为 0.0 |
| `liquidation_share` | 恒为 0.0 |
| `liquidation_z` | 恒为 0.0 |

**7/30 = 23% 的特征列是常数 0**。这些列不携带任何信息，
却参与了 LightGBM 的分裂搜索和 CatBoost 的特征组合，
等于把一部分模型容量分配给了纯噪声——在信噪比本来就极低的问题上，这是纯损失。

剩下的 23 个特征主要来自三个族：价格动量（EMA/RSI/return）、
资金费/基差、持仓量/多空比。这些是**全市场共有的、被广泛研究的因子**，
意味着它们的 alpha 早已被套利掉。

### 根因 3：横截面池化 + 12 个品种，样本量被高估

`train.py` 把 12 个品种的 126 万行混合成一个池训练单一模型。
但：
- 三重障碍窗口重叠严重（mean bars_held 6.36，horizon 12），
  行与行之间高度自相关。尽管已经实现了 uniqueness weights，
  **有效独立样本数远小于 126 万**——可能只有其 1/10。
- 12 个品种、约 1 年数据，在截面维度上覆盖太窄，
  模型学到的主要是"这一年的市场状态"，而不是可泛化的规律。
- 样本外亏损随时间加剧（fold 4 一致性地最差），是典型的**非平稳 + 过拟合**特征。

## 四、训练方法该怎么改（如果坚持在这个方向迭代）

按**预期收益排序**：

### 1. 先做特征审计（1 小时，必做）
把 7 个常数列删掉，并把"特征是否常量化"做成训练前的硬门禁。
你现在有 `profile_dataset.py`，但没有把"某列在所有数据上是常数"判为致命错误。
在 1.26M 行上都恒为 0 的列，永远不该进入模型。

### 2. 用 meta-labeling 替代直接预测方向（Lopez de Prado）
这是最可能产生实质改善的一步：
- **第一层模型**：用简单、稳健的规则产生方向（比如趋势跟随、资金费套利方向）。
- **第二层模型**：预测"这笔交易是否会盈利"（二分类），用三重障碍的 barrier 结果做标签。
- 第二层只回答**是否下手和多大仓位**，不回答方向。

为什么有效：把"预测方向"（信噪比极低）降级为"在已有方向上过滤"（信噪比高得多）。
你的 README 里已经提到了 meta-labeling 并做了 `edge_report`，但**没有把它接进训练主链**——
当前 `tabular_model.py` 仍然是直接回归 `future_return`。

### 3. 换目标变量：预测波动率/幅度，而不是方向
在 1 小时尺度上，**波动率是可预测的，方向不是**。这是一个稳健的、有大量文献支持的非对称性。
- 目标改为预测 `realized_vol` 或 `|return|`，用分位数回归输出区间。
- 用途：仓位 sizing（波动率目标）、选择何时**不**交易、给期权/网格类策略定价。
- 这不会让你"预测涨跌"，但会让你的风险层从拍脑袋变成有依据。

### 4. 用 CPCV 替代单次 walk-forward
当前 `walkforward.py` 是扩展窗口的 4 折。4 折的 OOS 样本太少（active_samples 只有 37~1434），
bootstrap 置信区间宽到 −38 ~ +16 bp，**根本无法区分"没信号"和"有信号但样本不够"**。
CPCV（Combinatorial Purged CV）用 N 组、k 折组合出 C(N,k) 条路径，
能在同样数据下给出远更紧的分布。mlfinlab 有现成实现。

### 5. 特征侧的真实增量（而非再堆技术指标）
技术指标类特征已经饱和。有文献支持、且你**尚未使用**的：
- **分数阶差分**（fractional differentiation）：整数差分（你的 return_10）会摧毁记忆性，
  分数阶差分保留长记忆同时获得平稳性。
- **横截面排序/中性化**：把每个特征在该时刻对 12 个品种做 rank 与 demean，
  剔除市场 beta，只留相对强弱。这是截面策略的标准做法，你现在做的是时间序列归一化。
- **微观结构**：order flow imbalance 需要买卖盘口快照，不是 K 线聚合量。

### 6. 缩短单笔持仓、提高换手对应降低成本
当前 mean bars_held = 6.36（约 32 分钟），却付 12bp 往返。
如果走 maker 挂单（2bp 而非 4~5bp taker），成本降到约 4~6bp，
所需 edge 从 0.17σ 降到约 0.08σ——**成本侧的努力比模型侧的努力回报更高**。

## 五、更诚实的建议：改变问题，而不是继续调这个模型

有证据支持、真正能赚钱的加密永续边（edge）**不是**短周期方向预测：

| 边类型 | 证据强度 | 大致量级 | 说明 |
|---|---|---|---|
| **资金费套利 / 现金持有（basis carry）** | 强 | 年化 5%~15%，Sharpe 1~3 | 现货多头 + 永续空头收资金费。市场中性，与方向无关。**你的系统已经采集了资金费和标记价，但只把它当特征，没当策略。** |
| **截面动量 / 短期反转** | 中强 | 日频，Sharpe 0.5~1.5 | 在品种之间做多强弱排序。需要横截面，你已有 12 个品种（偏少但可用） |
| **时序动量 / 趋势跟踪** | 中 | 数日~数周 | 最经典、最resilient，但需要持仓数天而非数十分钟 |
| **清算级联后的均值回归** | 中 | 事件驱动 | 你采集了 liquidation 数据，但全是 0（采集未接通）；接通后可做事件策略 |
| **波动率风险溢价** | 中 | 期权市场 | 需要期权数据 |

**关键洞察：你的系统已经在采集资金费、持仓量、多空比、清算流——
这些数据最有价值的用法是做 carry 和事件驱动策略，而不是喂给一个预测方向的 GBDT。**

### 建议的重新设计

```
方向 A（推荐，风险最低）：
  资金费 carry 策略
  - 目标：市场中性，赚取资金费 + 基差收敛
  - 数据：你已有的 funding_rate / mark_basis / 现货价
  - 持仓：数小时到数天（成本摊薄）
  - 预期：年化 5~15%，Sharpe 1~3，回撤可控
  - 模型角色：预测资金费走向 + 基差风险，而非价格方向

方向 B（中等难度）：
  截面动量的第二层过滤（meta-labeling）
  - 第一层：12 品种的截面动量信号
  - 第二层：GBDT 预测该信号下哪些品种/时段值得下手
  - 持仓：小时级到日级

方向 C（放弃）：
  5 分钟 K 线的 1 小时方向预测
  - 已被你自己的 16 个 manifest 证伪
```

## 六、不要做什么（明确的死路）

1. **不要再堆技术指标**。EMA/RSI 的组合早已被套利尽。
   加到 100 个特征只会让过拟合更快、OOS 更差。
2. **不要换更复杂的模型**（LSTM/TFT/Transformer）。
   在 R² < 0.1% 的问题上，模型容量不是瓶颈，**信噪比才是**。
   换模型只会得到更漂亮的 in-sample 和同样的 OOS 亏损。
3. **不要继续调 `MODEL_MIN_EDGE_BPS` 之类的阈值**。
   把阈值提高只会让 active_share 从 0.35% 降到 0，模型仍然没有信号。
   你当前 `active_share_pct` 已经低到 0.02%，说明模型自己也"知道"没把握。
4. **不要相信校准改善**。当前 isotonic 让 ECE 从 0.007 变到 0.49，
   这是在拟合噪声。**校准不能创造信息，只能重排已有的信息。**
5. **不要忽略那 7 个死特征**——但也不要以为修好它们就能翻盘。
   修好最多让模型从 50.0% 到 50.3%，因为问题在标签-成本结构。
6. **不要在 5 分钟尺度上做方向预测并付 taker 费率**。
   成本 0.17σ、需要预测 R² > 3%，这是信息论层面的不可能。

## 七、执行顺序

| 步骤 | 动作 | 判定成功的标准 | 预计耗时 |
|---|---|---|---|
| 1 | 接上 7 个死特征的采集，或从 FEATURE_SETS 中移除 | profile 中无常数特征 | 半天 |
| 2 | 接入 mlfinlab 的 **CPCV**，重跑现有模型 | 得到 −x ~ +y bp 的紧致置信区间 | 1 天 |
| 3 | 实现 **meta-labeling** 第二层并接入训练主链 | 第二层 OOS AUC > 0.53 | 2~3 天 |
| 4 | 用**波动率预测**替代方向预测，接到仓位 sizing | 波动率预测 OOS R² > 0（这个**是**可达到的） | 2 天 |
| 5 | 用现有 funding/mark 数据实现**资金费 carry 策略**并独立回测 | 扣费后 Sharpe > 1 | 3~5 天 |
| 6 | 若 2~4 步后方向模型扣费边际仍 < 0，**放弃方向预测路线** | — | 决策点 |

**第 6 步是认真的。** 在投入更多时间之前，先让第 5 步（carry 策略）
给出一个正的、成本可覆盖的收益曲线——那条边是有文献支持的，
比你正在追的方向预测边可靠得多。

## 八、一句话总结

> 你的工程实现是扎实的——三重障碍、uniqueness weights、purged walk-forward、
> deflated Sharpe、isotonic 校准，这些都比大多数业余项目做得好得多。
> **问题不在工程，在选题：你要求模型预测一个噪声比信号大一个数量级、
> 且成本占 0.17σ 的方向。** 16 个候选模型一致失败不是巧合，
> 是这个问题的正确答案。把同样的工程质量用在资金费 carry 和
> meta-labeling 过滤上，才可能得到正期望。
