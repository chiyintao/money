# 为什么是 49.23%：追到底层

问"H 49.23% 够不够"，答案是**不够，而且原因不在模型，在数据**。

## 发现 1：7 个特征是恒为 0 的死列

33 个声明特征里，**7 个在全部 40,000 行中恒等于 0.0**：

```
flow_delta_ratio        constant = 0.0
flow_delta_z            constant = 0.0
flow_largest_trade_z    constant = 0.0
flow_trade_intensity_z  constant = 0.0
liquidation_pressure    constant = 0.0
liquidation_share       constant = 0.0
liquidation_z           constant = 0.0
```

全部订单流（order flow）与强平（liquidation）特征。**21% 的特征空间是空的。**

代码没问题 —— `app/features/order_flow.py` 里这些特征都实现了，`feature_spec.py` 里也声明了。
问题在数据源。

## 发现 2：数据源覆盖 0.25%

| 表 | 行数 |
|---|---|
| `candles` | 3,533,475 |
| **`flow`** | **8,674（0.2455%）** |
| `derivatives_detail` | 1,274,337 |

- `flow` 只覆盖 **12 个币种**，而 candles 有 **62 个**
- `flow` 中强平列**只在 1,050 / 8,674 行非零（12%）**
- 模型实际交易的币种里，**50 个完全没有 flow 数据**

这不是代码 bug，是**采集缺口**。特征被正确计算了，只是输入是空数组，于是回落到 0.0 默认值。

## 发现 3：剩下的 26 个特征几乎没有信息量

对 `future_return` 的相关性（n=60,000，噪声下限 **0.0080**）：

| 特征 | Spearman | 是否超过噪声 |
|---|---|---|
| `return_10` | -0.0266 | 是（3.3×） |
| `bars_held` | 0.0306 | 是（3.8×） |
| `funding_carry_24h` | 0.0240 | 是（3.0×） |
| `funding_rate` | 0.0230 | 是（2.9×） |
| `ema20_gap` | 0.0212 | 是（2.6×） |
| `long_short_ratio_z` | -0.0180 | 是（2.2×） |
| `quote_volume_ratio` | 0.0006 | **否** |
| `ema50_gap` | -0.0020 | **否** |

**最强信号 |Spearman| ≈ 0.03。** 这意味着即使完美利用，也只能解释 0.1% 的方差。

（注：`future_return` 与 `label_start` 出现在表中是标签泄漏，应排除。）

## 结论

49.23% 不是模型没调好，而是**输入里本来就没有多少可学的东西**：

1. **21% 的特征是死列**（数据从未采集）
2. **剩下一半特征的相关性低于或接近噪声下限**
3. **最强特征解释 0.1% 方差** —— 而往返成本是 8-12bp，
   信号量级（0.03 × 日波动）远小于成本

## 什么才真正有用

### 优先级 1：补上 flow 数据（最高杠杆）

这是唯一一个"补数据 → 特征立刻活过来"的动作。
强平和订单流是加密市场里少数有真实预测力的微观结构信号，
而当前 50/62 个币种是空的。

**动作**：把 flow 采集扩展到全部 62 个币种，回填历史，然后重训。

### 优先级 2：如果补不上，就承认特征不足

用现存 26 个特征重训不会改变什么。诚实的选择是：
- 要么接受当前模型不能预测方向（停掉实盘）
- 要么换问题：不做方向预测，做**波动率预测**或**执行优化**
  （波动率有强自相关，是可预测的；方向不是）

### 优先级 3：不要继续调门限

我前两轮改的门限、标签、风控都是正确的工程修复，
但**没有一个能让 0.03 的相关性变成钱**。

## 一句话

> 不是模型太笨，是喂给它的 21% 是 0，剩下的最强信号只解释 0.1% 的方差。
> 在补上数据之前，任何调参都是在噪声里找规律。
