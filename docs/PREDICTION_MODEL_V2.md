## 一、诊断结论：模型在预测波动率，不是在预测方向

这是本轮最重要的发现，也是解释全部 16 个候选模型失败的根因。

对 8 万行做组合purged交叉验证（6 组、取 2 组、14 个 split），逐 split 测量：

| 度量 | 均值 | 含义 |
|---|---|---|
| 方向准确率 | **0.4918** | 抛硬币 |
| `corr(预测, 实际)` 带符号 | **+0.0284** | 方向信息几乎为零 |
| `corr(\|预测\|, \|实际\|)` | **0.319** | 幅度预测**相当强** |
| `corr(\|预测\|, atr_pct)` | **0.443** | 它主要在读 ATR |

**模型学到的是"这根 K 线会动多大"，不是"往哪边动"。**

为什么会有这个假象：三重障碍的止盈止损是 **ATR 的倍数**，所以标签的
**幅度**在构造上就由 ATR 决定。实测 `corr(atr_pct, |future_return|) = 0.811`，
而 `corr(atr_pct, sign(future_return)) = 0.030`。
GBDT 去拟合一个幅度被 ATR 决定的标签，第一件事就是学会预测 ATR——它做得很好，
然后这个能力被误读成了"预测能力"。

### 决定性对照实验

如果"优势"只是波动率选择，那么一个只按 ATR 选标的的**随机方向**策略应当同样赚钱：

```
策略                       edge_bps     交易数
MODEL (GBDT)                  +2.26       9746
vol-only momentum            -16.00      14240
vol-only RANDOM               -0.71      14270
```

模型确实**高于**两个波动率基线，说明它含有**一点**真实方向信息——
但只有 **+2.26 bps**，远不足以覆盖成本，更不足以稳定盈利。
这解释了为什么换模型、调参、加特征都无济于事。

## 二、根因：horizon 选错了，它在反转区而不是动量区

对 12 个品种 366 天实测**符号持续性**（过去收益符号与未来收益符号的相关，
非重叠采样）：

| horizon | 符号持续性 | 市场状态 |
|---|---|---|
| 5 分钟 | **-0.023** | 反转 |
| 30 分钟 | **-0.031** | 反转 |
| 2 小时 | **-0.020** | 反转 |
| 1 天（288 bar） | **+0.060** | **动量** |
| 2 天 | -0.020 | 噪声 |

**信号方向随 horizon 变号。** 全部候选模型都训练在 1 小时——
正处在反转区，而且那个 -0.02 的信号强度，理论最高准确率不到 51%，
与实测的 49.2%~51.7% 完全吻合。

## 三、替代方案：横截面动量（日频），实测大幅更优

把问题从"这个币会涨吗"改成"哪些币比其他的更强"。

### 实测结果（31 个品种、366 天、非重叠交易、双边 12bps 成本）

```
7 天 lookback / 1 天持仓 / 上下各 25%
356 笔非重叠交易，扣费后 +78.2 bps/笔
t = 3.37，Sharpe = 3.41，胜率 55.6%
前半段 87.8 bps，后半段 68.6 bps
13 个月中 10 个月为正
```

### 这不是过拟合的参数，是平台区

```
lookback   hold=1     hold=3     hold=7
       1   21/1.6     59/1.5    171/1.8
       3   33/2.1     40/0.9    264/2.2
       7   36/2.6    104/2.2    202/1.7
      14   31/2.3     80/1.7    292/2.4
      21    7/0.5     21/0.5    111/1.0
      30   -7/-0.5     1/0.0    -54/-0.5
```

- lookback 1~14 天、所有分位数（0.1~0.4）**全部为正**
- 21~30 天衰减到零——说明长周期动量已被套利，短周期还没有
- 单位：净 bps / t 统计量

### 稳健性

- **逐符号剔除检验**：31 个品种分别剔除后，**31/31 仍为正**（最差 48.3 bps）
- 两个半边各自独立为正（87.8 / 68.6 bps）
- 分位数从 0.10 到 0.40 全部为正（63.7 到 21.1 bps）

## 四、新增的代码

### 数据质量：`app/models/feature_audit.py`

训练前审计每个特征列。**独立复现了 7 个死列**：

```
flow_delta_ratio, flow_delta_z, flow_trade_intensity_z, flow_largest_trade_z,
liquidation_pressure, liquidation_share, liquidation_z   —— 全部恒为 0.0
```

`flow` 表只有 8,854 行，而 K 线有 350 万行，所以整个族都退化成默认值。
**30 个特征里 7 个是常数，占模型容量 23.3%。** 在信噪比是瓶颈的问题上，
树模型仍会枚举这些列，这部分容量是净损失。

区分三种缺陷（需要不同的处理）：
- `constant` —— 完全没有方差，必须删除或修采集器
- `degenerate` —— 有极少变化（罕见事件特征合法，只报告不删除）
- `unmeasured` —— 大量缺失，是采集问题

### 诚实验证：`app/models/cpcv.py`

组合purged交叉验证 + 回测过拟合概率（PBO）。

- N=8、k=2 产生 **28 个测试集、7 条完整路径**（原来只有 4 折）
- 原 4 折的 bootstrap 区间是 **-38 ~ +16 bps**，宽到无法做任何判断
- **purge + embargo 都实现**：purge 覆盖标签前向可达，embargo 覆盖特征后向可达。
  只做其中一个，是"以为做了purge其实没有"的标准错法
- PBO 回答的是"选择程序本身是否可泛化"，这是单一 deflated Sharpe 答不了的

### 成本可行性门禁：`app/models/label_economics.py`

在训练**之前**判断标签能否付得起自己的交易成本：

```
标签标准差 76.5 bps ÷ 往返成本 6 bps = 0.078 sigma
盈亏平衡需要 R² ≥ 0.61%；日内加密实际可解释 R² 约 0.3%
→ 当前 12-bar horizon 标注 INFEASIBLE
```

并给出"需要多长 horizon 才够"的计算：

```
taker 6bps + R²=0.3%  →  需要 24 根（2 小时）
maker 3bps + R²=0.3%  →  需要  6 根（30 分钟）
taker 6bps + R²=0.1%  →  需要 70 根（350 分钟）
```

### 改进的训练管线：`app/models/improved_training.py`

保留原有正确部分（池化、purged split、uniqueness weights、isotonic），新增：
审计门禁、经济学门禁、second-stage meta-labeling 接口、CPCV 验证。

### 替代策略：`app/strategy/cross_sectional.py`

横截面动量信号生成器，输出目标权重（多空各 25%，美元中性）。
**只产生信号，不下单**——仓位、风控、执行仍交给已有层次。

### 复现入口：`scripts/research_v2.py`

```bash
python -m scripts.research_v2 audit      # 特征审计
python -m scripts.research_v2 economics  # 成本可行性
python -m scripts.research_v2 validate   # CPCV 验证
python -m scripts.research_v2 momentum   # 横截面动量证据
python -m scripts.research_v2 momentum --scan   # 参数平台扫描
```

## 五、一个被忽略的关键点：成本假设高估了一倍

原 harness 用 **12 bps** 往返，实测 Binance USDT-M 标准档应为：

| 执行方式 | 手续费 | 价差 | 冲击 | 合计 |
|---|---|---|---|---|
| taker | 4.0 | 1.0 | 1.0 | **6.0 bps** |
| maker | 2.0 | 0.0 | 1.0 | **3.0 bps** |

用 12bps 评估，等于把所有策略的门槛抬高了一倍。
**改用 maker 执行（3bps），所需 R² 从 0.61% 降到 0.15%**——
成本侧的努力比模型侧的努力回报更高。

## 六、建议的下一步

| 优先级 | 动作 | 依据 |
|---|---|---|
| 1 | 用 `research_v2 momentum` 对横截面动量做**前向纸面跟踪** | 实测 t=3.37、逐符号剔除 31/31 为正 |
| 2 | 修 `flow` 采集器（8,854 行 vs 350 万 K 线），或从特征集移除该族 | 7/30 特征为常数 |
| 3 | 若坚持方向预测，把 horizon 从 12 bar 提到 **24~70 bar** | 经济学门禁计算 |
| 4 | 执行改为 maker 挂单 | 成本 6→3 bps，所需 R² 降 4 倍 |
| 5 | 用 CPCV 替代 4 折 walk-forward 评估所有新模型 | 原区间 -38~+16 bps 无法决策 |
| 6 | 停止在 5 分钟 horizon 上做方向预测 | 反转区 + 成本 0.078σ |

### 不要做

1. **不要换更复杂的模型**（LSTM/TFT）——问题在信噪比，不在容量
2. **不要继续堆技术指标**——EMA/RSI 组合已被套利尽
3. **不要相信 in-sample 提升**——幅度 R²=9% 是 ATR 假象
4. **不要把 `atr_pct` 的高相关当作方向信号**——它是 0.030 的方向相关
5. **不要在没有 embargo 的情况下声称做了 purged CV**

## 七、诚实的边界

- 横截面动量的 t=3.37 是在**同一段历史内**的分半检验，不是真正的样本外。
  需要前向纸面跟踪才能确认。
- 31 个品种、366 天、13 个月，样本仍然有限；13 个月里 10 个月为正。
- 未计入：资金费（多空对冲后应接近中性）、借币成本、极端行情下的流动性。
- 未验证容量上限：25% 分位在 31 个品种上约 8 个多头 + 8 个空头。
- 本轮的 web 搜索因 Firecrawl 免费额度限流未能完成外部项目对比，
  所有结论均基于**本仓库数据实测**。外部开源项目（qlib / mlfinlab / FreqAI / Kronos）
  的调研结论见 `MODEL_DIAGNOSIS_AND_REDESIGN.md`。
