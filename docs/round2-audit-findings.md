# 多轮审查发现（第 2 轮）

本轮的目标是复核第一轮修复，并继续深挖。结论有一个重要的自我更正。

## 1. 标签与执行平局规则不一致 —— 影响远小于我此前的说法

**修复仍然正确，但我上一轮给出的量级是错的。**

我用真实 BTCUSDT 5 分钟 K 线（30,000 根，5,998 个样本）分别按两种规则重新打标签：

| 指标 | 数值 |
|---|---|
| 翻转行数 | **5 / 5998 = 0.08%** |
| 乐观规则胜率 | 32.29% |
| 实际执行规则胜率 | 32.13% |

我此前的"5.8% 乐观偏差"来自无条件的均值比较（|upper| 0.00676 vs |lower| 0.00653），
它把"目标离入场更远"当成了偏差，而那是 **reward:risk = 1.6 的必然结果**，不是缺陷。
最初那个 87.2% 的估计更糟：它只问"K 线振幅是否够大"，没问是否真的同时触及两个价位。
真实上界是 4.98%，实际翻转是 0.08%。

**但这条规则并非无关紧要。** 翻转率随止损宽度相对波动率变化：

| 几何 | 翻转率 |
|---|---|
| 30bp 止损 / 48bp 目标（当前实盘） | 0.08% |
| 30bp / 48bp，1 根 K 线horizon | 0.03% |
| **10bp / 16bp（更紧的止损）** | **3.23%** |

紧止损策略恰好落在翻转率最高的区间。测试文档中的表述已按实测更正。

## 2. 静默默认值扫描

`trials=1` 的特征是"默认值关闭了安全检查"。用 AST 扫描 `app/` 全树，找到 4 处同类形状：

| 位置 | 参数 | 默认值 | 影响 |
|---|---|---|---|
| `strategy/live_models.py:642` | `require_promoted` | `False` | 未通过审核的权重可以交易 |
| `strategy/symbol_edge.py:50` | `fdr` | `0.0` | 不做多重检验校正 |
| `strategy/symbol_edge.py:50` | `min_net_bps` | `0.0` | 门限不拦负期望 |
| `storage/storage.py:210` | `check_gaps` | `False` | 不检查 K 线缺口 |

## 3. 当前配置的实际决策面（1959 条真实决策）

| edge_bps 区间 | 条数 | 占比 |
|---|---|---|
| < -1.5（拒绝） | 1656 | 84.5% |
| **[-1.5, 0) 负期望但仍放行** | **119** | **6.1%** |
| [0, 5) | 184 | 9.4% |
| >= 5 | 0 | 0.0% |

- `edge_bps` 已扣除完整往返成本，因此 `[-1.5, 0)` 是**模型自己认为会亏**的区间，均值 **-0.54bp**
- **没有任何一条决策达到 5bp 以上 edge**
- `MODEL_MIN_EDGE_BPS=-1.5`、`SYMBOL_EDGE_ENABLED=0`、`MODEL_REQUIRE_PROMOTED=0`（`.env` 未设置，取默认）

### 最值得注意的一条

在 303 条通过 `ensemble_agrees` 的信号中，**298 条（98.3%）带 `out_of_distribution_warning`**。
越界输入的预测不是"不确定"，而是"没有依据"。当前策略是 `warn`，所以照常交易。

## 4. 前端：告警被淹没

`reason_codes` 原本全部拼进同一个灰色单元格，所以
`out_of_distribution_warning` 和 `ensemble_agrees` 看起来一模一样。
已改为：告警类代码单独用 `down` 样式高亮，`candidate` 权重显示为"未通过审核"。

## 仍成立的第一轮修复

1. **标签平局规则** —— 默认跟随执行（影响 0.08%，但正确）
2. **deflated Sharpe `trials`** —— 现在必填、校验、写入 manifest（影响真实：DSR 0.9999 → 0.938）
3. **对账告警不可见** —— 已渲染，`_direction` 不再把缺失方向当卖出
4. **`account_reconcile` 移入 `ops/`** —— 消除 `strategy → backtest` 违规依赖

## 诚实结论

系统自身的评估是诚实且正确的：方向准确率 49.23%（抛硬币），
活跃样本占比 0.019%（189,961 行中仅 37 行），verdict 明确写着"未建立 edge"。

**这些修复不能创造 edge。** 它们消除的是系统欺骗自己的途径 —— 这有真实价值，
因为无法测量就无法修复。但没有任何标签、门限或仓位修正能让 49% 方向准确率的模型盈利。

投资回报率最高的下一步不是再改代码，而是**用修正后的标签重训**，
看样本外收益能否离开 -10.33bp。如果不能，问题在特征本身。
