## 一、先说结论

我把这个项目之前所有失败的原因定位到了**三个可以测量的具体错误**，而不是"模型不够强"：

| 之前的问题 | 实测证据 | 本次的修正 |
|---|---|---|
| 1 小时视野处在**反转区** | 符号持续性：5 分钟 -0.023、2 小时 -0.020、**1 天 +0.060** | 全部改到**日频**（1 天持有） |
| 特征里 **23% 是死列** | 30 个特征中 7 个恒为 0 | 新面板**零死列**，覆盖率入档 |
| **训练域 ≠ 交易域** | 文档里的 +78.2bp 边是在 31 币池上测的 | 固定 **14 币篮子**，同一批币训练/验证/决策 |

修正之后：

**在 366 天（2025-09 → 2026-09）上：**

```
第一层（排序模型，样本外 261 天）
  suite    37.5 bp/笔   t=2.04   截面 rank IC = 0.0421
  对照规则  45.4 bp/笔   t=2.03   （原始 7 日动量，同一时间窗）

第二层（决策层，样本外 255 天）
  +15.0 bp/天   t=2.35   Sharpe 2.81   平均总仓位 67.6%
  成本从 6bp 加到 20bp，结论不变（t 始终 > 2）
```

**在把历史扩到 894 天（2024-04 → 2026-09）之后，同一个规则是：**

```
对照规则  全历史 +25.8 bp/笔 (t=2.14)   其中新增的 527 天为 -0.2 bp (t=-0.01)
第二层    +7.3 bp/天 (t=1.95)，前半段 -4.3
成本 25bp/边：全历史 -12.2 bp/笔 (t=-1.01)  ← 真实吃单成本下不赚钱
```

**必须说清楚三件事，否则上面的数字会被误读：**

1. **上一段的 +62.9bp 是一个 12 个月窗口的产物。** 扩数据后新增的 17 个月收益为零。
   详见下面"一之二"。
2. **拟合出来的模型没有跑赢一个免费的规则。** 第一层 37.5bp < 对照规则 45.4bp，5 折里只有 1 折胜出。
   在 6 倍数据上这个结论不变（5 个滚动窗口输 4 个）。我把结果**写进了模型文件本身**。
3. **第二层是"风险控制版"而不是"更赚钱版"。** 它在亏损的那一折把 -16.2bp 收敛到 -4.9bp，
   但在赚钱的几折让出约三分之一的收益（34.2 vs 48.0，22.4 vs 61.8）。

## 一之二、扩展历史之后：最重要的发现

上一节的数字全部基于 **366 天**（2025-09 → 2026-09）。我把它扩到了 **894 天**（2024-04 → 2026-09），
方法是从 Binance 官方归档下载 14 个币的**全部月度 5m K 线**（`scripts/extend_history.py`）：

- 新增 **4,904,224 行**（1,053,140 → 7,957,364），历史从 1 年扩到 **6.6 年**
- BTC/ETH/XRP/ADA/LINK 回溯到 2020-01；ENA 到 2024-04（合约那时才上线）
- 面板 **366 天 → 894 天**（12,516 行），仍然零死列

**然后结论变了，而且是往坏的方向变：**

| 时间窗 | 天数 | 规则净收益 | t |
|---|---|---|---|
| **2025-09 → 2026-09**（上一节用的窗口） | 365 | **+63.4 bp** | **3.35** |
| 2024-04 → 2025-08（新增的 17 个月） | 527 | **−0.2 bp** | **−0.01** |
| 2024-04 → 2026-09（全部） | 893 | **+25.8 bp** | 2.14 |

逐月收益（bp）显示得很清楚：

```
2025-08:   -8   2025-09:  206   2025-10:  131   2025-11:  145
2025-12:   -3   2026-01:   17   2026-02:   -8   2026-03:   15
...
2025-03: -187   2024-10:  -44   2024-12:  -36   2024-07:  -35
```

**上一节报告的 +62.9 bp / t=3.27 是一个 12 个月窗口的产物。** 在那个窗口之前的 17 个月里，
同一个规则、同一个篮子、同一个成本，收益是 **−0.2 bp**。

这不是说模型坏了，而是说**它从来就没有被真正检验过**：一个 t=3.35 的结果，
在样本外的 17 个月里归零。这正是我在上一节第七节写下的"样本只有 366 天、可能只是一种市场状态"——
现在这句话有了具体数字。

**成本更致命。** 把成本从 6bp/边提到 25bp/边（更接近真实吃单）：

| 时间窗 | 6 bp/边 | 25 bp/边 |
|---|---|---|
| 2025-09 → 2026-09 | +63.4 (t=3.35) | +25.4 (t=1.34) |
| 2024-04 → 2026-09 | +25.8 (t=2.14) | **−12.2 (t=−1.01)** |

在完整历史上、以真实成本计，**这个策略不赚钱**。

### 收缩结论在 6 倍数据上依然成立

上一节的核心建模结论是"拟合层不该有话语权"。用 6 倍数据重做滚动实验（拟合 0..k，测其后 120 天）：

| 拟合到第 k 天 | 原始 ret_7d | 未收缩 ridge |
|---|---|---|
| 240 | +1.9 bp | −16.6 bp |
| 365 | +2.1 bp | −35.5 bp |
| 480 | −47.3 bp | −3.1 bp |
| 600 | +12.2 bp | −35.7 bp |
| 720 | −33.9 bp | **−61.4 bp** |

**5 个窗口里未收缩的 ridge 输了 4 个。** 样本量增加 2.4 倍并没有让拟合变得可用——
这和"数据不够所以过拟合"的直觉相反，也更值得记住。

### 这一节改变了什么

1. **`docs/COIN_SUITE_MODEL.md` 第二节的 +62.9bp 必须加上窗口限定**，它不是全历史结论。
2. **决策层的 +15.0 bp/天 降为 +7.3 bp/天（t=1.95）**，在前半段为负（−4.3）。
3. **"下一步"的第一条从"前向跟踪"变成了"先确认边缘是否真实存在"**——完整历史上它可能是零。
4. **历史上限 894 天不是数据问题，是策略问题**：扩数据的作用是把一个假阳性证伪，
   而不是把一个真阳性变强。

## 二、最重要的一条：训练域必须等于交易域

这是本次最贵的发现，也是之前所有报告都算错的地方。

文档里写着横截面动量 **+78.2 bp/笔，t=3.37**。我用同一个引擎、同一个参数，只换币池：

| 币池 | 币数 | 净收益 | t |
|---|---|---|---|
| 原 12 个主流币 | 12 | **−11.7 bp** | −1.23 |
| 流动性前 12 | 12 | +49.3 bp | 2.57 |
| **流动性前 14（本次采用）** | 14 | **+62.9 bp** | **3.27** |
| 原文档的 31 币 | 31 | +78.2 bp | 3.37 |

**+78.2bp 的边在 12 个主流币上根本不存在，它是 −11.7bp。** 那 78bp 来自小市值币。

机制是清楚的：截面信号需要**离散度**才能排序。12 个同涨同跌的大币之间几乎没有相对强弱可赚；
而 BTC（日均波动 0.24%）与 ZEC（1.4%）之间才有真正的价差。

**本次采用的 14 币篮子**（按流动性规则选出，日成交额 ≥ 8000 万美元）：

```
BTCUSDT ETHUSDT SOLUSDT ZECUSDT XRPUSDT DOGEUSDT BNBUSDT
WLDUSDT ADAUSDT NEARUSDT SUIUSDT ENAUSDT LINKUSDT UNIUSDT
```

稳健性检验（7 日回看 / 1 日持有 / 上下各 25%）：

| 检验 | 结果 |
|---|---|
| 成本 6 → 25 bp/边 | 62.9 → 24.9 bp，单调递减，合理 |
| 逐币剔除 | 14/14 全为正（最差剔除 ZEC 后仍 +23.0bp） |
| 参数平台 | 7 日回看最佳，但 3/5/10/14 日全为正 |
| 分半 | 前半 70.3bp，后半 55.6bp，两半皆正 |
| 13 个月 | 11 个月为正 |

## 三、第二重要的一条：拟合在这个样本量上会吃掉信号

我**没有**假设"更强的模型更好"，而是直接测了。滚动实验：用 0..k 天拟合，测其后 60 天，
把拟合成分和它赖以构建的**原始单列**对比：

| 拟合到第 k 天 | 原始 ret_7d（IC / 净收益） | 未收缩的 ridge（IC / 净收益） |
|---|---|---|
| 90 | +0.0522 / +20.2 bp | +0.0981 / +57.6 bp |
| 120 | +0.0040 / −4.6 bp | +0.0491 / +7.1 bp |
| 150 | −0.0277 / +24.5 bp | −0.0410 / **−61.9 bp** |
| 180 | +0.0409 / +45.8 bp | −0.0079 / **−77.6 bp** |
| 210 | +0.0192 / +52.3 bp | +0.0170 / **−72.1 bp** |
| 240 | +0.0083 / +70.0 bp | −0.0036 / −68.4 bp |
| 270 | +0.0276 / +46.9 bp | −0.0055 / −6.2 bp |

**7 个窗口里拟合版只赢了 1 个，后 6 个平均输约 80bp。**

而且可以看到那个典型的信号——**样本内 IC 越高，样本外越差**：

| 配置 | 样本内 IC | 样本外净收益 |
|---|---|---|
| 收缩 0.0（=原始列） | 0.0648 | **+30.2 bp** |
| 收缩 0.35 | 0.0751 | +30.2 bp |
| 收缩 1.0（纯 ridge） | **0.1546** | **−47.6 bp** |

样本内 IC 0.155 对应样本外 −47.6bp；样本内 IC 0.065 对应 +30.2bp。

所以 `SHRINK_TO_PRIOR = 0.0`：动量成分被完全收缩回原始 7 日排名。这不是放弃，
是**用同一批数据、同一套回测，测出了"拟合层不该有话语权"这个结论并据此设参**。
拟合出来的系数仍然全部存在 artifact 里，读者可以自行设回 1.0 复现反证。

## 四、第三重要的一条：决策层里有两个会悄悄吃掉收益的 bug

这两个都不是模型问题，是**工程问题**，而且它们在输出里完全看不出来。

### Bug 1：用"市场风险"给"市场中性组合"定仓位

第一版用加权波动率的平方和（假设不相关）估计组合风险。对**美元中性**的组合这是方向性错误：
多空两条腿都是加密资产，共同的市场 beta 会**互相抵消**，剩下的是小得多的相对价值离散度。

```
错误版本报告：日均波动 0.248，目标是 0.087  → 杠杆被压到 0.35
实际效果：37bp 的边被缩放成 0.9bp/天
```

修正方式是**用面板自己的数据估一个腿间相关系数**（而非假设），修正后：

| 版本 | 净收益 | 暴露 |
|---|---|---|
| 无相关项（错误） | 0.9 bp/天 | 0.455 |
| 有相关项（修正） | **7.9 bp/天** | 0.374 |

### Bug 2：成本过滤用在了"选腿之前"

在第一版里，成本过滤会剔掉排名靠近零的币——而那恰好是美元中性组合**多空两条腿开始重叠**的地方。
结果是"多"和"空"都从排序中段选出，**组合不再是一个价差**。样本日上 8 条腿被砍成 6 条（各 3 条），全部来自中段。

改成**先选极端腿、再对选中的腿做成本检验**之后：

| 版本 | 净收益 | t |
|---|---|---|
| 先过滤后选腿（错误） | 7.9 bp/天 | 2.24 |
| **先选腿后过滤（修正）** | **15.0 bp/天** | **2.35** |

顺带测出：**等权优于反波动率加权 16bp/天**（49.2 vs 32.8）。
原因是波动率与动量信号不独立——排名最高的币本来就是波动最大的那些，反波动率加权会系统性地
**压低信号最有信心的仓位**。这是教科书工具与信号打架的典型案例，实测为准。

## 五、模型结构

两层，各自独立验证。

### 第一层：排序模型（`app/models/coin_suite.py`）

预测的是**截面排名**，不是收益。原因：三重障碍标签的幅度在构造上由 ATR 决定
（`corr(atr_pct, |future_return|) = 0.811`，而 `corr(atr_pct, sign(future_return)) = 0.030`），
GBDT 拟合它学到的第一件事就是预测 ATR——这是之前"看起来有预测能力"的来源。

五个成分：

| 成分 | 做什么 | 状态 |
|---|---|---|
| momentum | 相对强弱 | **完全收缩回 7 日排名**（见第三节） |
| breakout | 突破确认：价格在区间位置 + OI 变化 + 主动买卖 | 保留拟合系数，样本外 IC 0.072 |
| regime | 市场状态标量 [-1,1] | 用于调节 momentum/breakout 的**混合权重** |
| meta | 元标签：这笔该不该做 | 已实现，报告为负结果 |
| risk | 预测未来波动率 | 仅用于仓位，**绝不用于方向** |

关于 regime，我在第一版写成了 `score * (1 + 0.5*regime)`，**它不可能有效果**：
regime 是**全市场标量**，同一天对所有币相同，而截面信号只关心排序——
乘一个正数常数完全不改变顺序。这个项曾经"存在、合理、且完全无效"。
改成调节两个视角的**混合权重**之后，IC 从 0.0117 升到 0.0280。

### 第二层：决策层（`app/models/coin_decision.py`）

回答四个模型答不了的问题：

1. **预测的边够不够付成本？** 把排名换成期望收益，减掉双腿成本，不够就拒绝并**记录原因码**。
2. **每腿多大？** 按波动率目标缩放整个组合（不是按名字），上限受 `MAX_WEIGHT_PER_COIN` 约束。
3. **今天该不该做？** regime 缩放总仓位。
4. **止损止盈在哪？** 用实盘同一个 `exit_policy` 对象。**训练用什么障碍，实盘就必须用什么障碍。**

## 六、数据面板（`app/models/daily_panel.py`）

- **366 天 × 14 币 = 5124 行**，覆盖本地全部已记录历史（2025-09-12 至 2026-09-12）
- **零死列**；各特征族最低覆盖率：carry 52%、momentum/trend/volatility 91%、positioning 92%、flow 0.14%（清算数据本地确实只有 0.14%）
- 面板**密封**：篮子、日历、列名、特征族的 sha256 摘要写进 artifact，验证时重算，
  **摘要不匹配就拒绝**——模型不能在一个它没见过的面板上被评分

一个容易错的技术点：**资金费是每 8 小时结算一次（每天 3 次）**，所以按日历日累加会
把"可变次数的结算"加成一个伪周期。修正是按**结算序列**读取（每第 3 条记录归为同一批次），
使每个 frame day 恰好对应 1 次结算。frame 原点是 2025-08-06（周三，正好是结算日），
因此**任何按天对齐的窗口里结算次数只取决于窗口长度**。

## 七、诚实的边界

**不要把这些数字当成承诺。**

1. **扩到 894 天之后，边缘基本消失了。** 规则在 2025-09→2026-09 是 +63.4bp (t=3.35)，
   在之前新增的 527 天是 **−0.2bp (t=−0.01)**。以 25bp/边计，全历史是 **−12.2bp**。
   这是本次最重的结论：**在完整历史上、以真实成本计，这个策略不赚钱。**
2. **第一层没有跑赢免费规则**（366 天上 37.5 vs 45.4bp；894 天上 5 个滚动窗口输 4 个）。
   扩 2.4 倍数据**没有**让拟合变得可用——这与"数据不够才过拟合"的直觉相反。
3. **第二层是风险控制版**，不是更赚钱版。它降低回撤也降低收益。
4. **未计入**：资金费实际收支、借币成本、极端行情流动性、容量上限。
5. **逐币剔除全为正，但 ZEC 单独贡献 40bp**——去掉它仍有 +23bp，但集中度值得警惕。
6. **年化换算依赖 67.6% 的平均总仓位假设**，实际执行会有滑点。
7. **这仍然是同一段历史内的检验，不是真正的样本外前向跟踪。**

## 八、怎么用

```bash
# 0. 扩展历史（约 16 分钟，下载约 4.9M 行；已有数据不会重复写）
python scripts/extend_history.py

# 1. 建面板（约 1 分钟）
python -m app.models.daily_panel --output data/research_v4/panel_mainstream.jsonl

# 2. 训练 + 验证 + 存 artifact（约 2 分钟）
python -m app.models.coin_suite --folds 6 --cost-bps 6
#    返回码 0 = 样本外为正，1 = 不为正，可直接用于 CI

# 3. 决策层回放 + 自身验证
python -m app.models.coin_decision --cost-bps 12

# 4. 用已有 artifact 回放，不重新训练
python -m app.models.coin_decision --dataset data/models/coin_suite/coinsuite-<stamp>
```

产物：

| 路径 | 内容 |
|---|---|
| `data/research_v4/panel_mainstream.jsonl` | 面板 + manifest（含覆盖率与摘要） |
| `data/models/coin_suite/coinsuite-<stamp>/` | `manifest.json`（判词、逐折结果、参数）+ 系数 + 样本外逐笔预测 + 元标签模型 |
| `data/research_v4/decision_replay.json` | 决策层逐日回放 |

每个 artifact 都带 **sha256 校验**，文件与 manifest 记录不符时 `load_suite` 直接抛错。

## 九、下一步（按投入产出排序）

1. **先确认边缘是否真实存在，再做任何事。** 扩数据的结果是：完整历史上以真实成本计不赚钱。
   在回答"这个边缘是零还是小"之前，做前向跟踪只是把一个未知数测得更精确。
   需要的证据是**逐年的正收益**，而不是更高的总 t 值。
2. **前向纸面跟踪**，但只作为确认手段。现有 `app/strategy/forward_track.py` 已经能做，
   接上新的评分函数即可。
3. **逐币剔除要在扩展后的历史上重做**。366 天上的"14/14 全为正"是在一个收益率被高估的
   窗口里做的，必须重测。
4. **成本实测**。25bp/边下全历史是负的，而 6bp/边下是正的——**这一项决定策略是否成立**，
   优先于任何建模工作。
5. **补清算数据**。flow 族覆盖率只有 0.06%，本地几乎没有。
6. **在确认边缘存在之前不要再加复杂模型**。两轮实测（第三节、一之二）都显示，
   更多数据没有让更复杂的拟合变得可用。
